# Профили до начала матча: выбор чемпиона и экран загрузки

Исследование: как начать собирать данные об игроках не с первой секунды матча,
как сейчас, а раньше — в выборе чемпиона и на экране загрузки.

## Почему сейчас поздно

Профили заказываются в `/api/profiles`, а он берёт состав из Live Client Data
API (`127.0.0.1:2999`). Этот API отвечает только когда матч уже загружен.
Лобби из десяти игроков — 30 запросов, при лимите personal-ключа
(20/с и 100/2 мин) это около сорока секунд. Итого первые полминуты матча
карточки пустые — ровно тогда, когда они нужнее всего.

## Что доступно на каждом этапе

| Этап | Сколько длится | Источник | Что известно |
|---|---|---|---|
| выбор чемпиона | 90–150 с | **LCU API** (клиент, `lockfile`) | ты сам; союзники — если клиент их показывает; пики и баны; назначенная роль |
| экран загрузки | 30–90 с | **spectator-v5** по своему puuid | все десять: puuid, Riot ID, чемпион, заклинания, команда |
| матч | — | Live Client (как сейчас) | табло |

### LCU API — клиент League

Неофициальный, но общеизвестный локальный API клиента (ARCHITECTURE.md §1
уже держит его третьим источником).

- **Где:** `https://127.0.0.1:<port>`, порт и пароль — в `lockfile`
  в каталоге установки (`D:\Riot Games\League of Legends\lockfile` на этой
  машине), формат `LeagueClient:<pid>:<port>:<password>:https`. Тот же порт
  и пароль есть в командной строке `LeagueClientUx.exe`
  (`--app-port`, `--remoting-auth-token`) — запасной путь, если каталог
  установки нестандартный.
- **Авторизация:** Basic, пользователь `riot`, пароль из lockfile.
  Пароль меняется при каждом запуске клиента — читать при подключении,
  никуда не сохранять и не логировать (то же правило, что для ключа Riot).
- **TLS:** самоподписанный сертификат Riot, как у Live Client. Уже решённая
  задача: `LiveClientSource` ходит в `:2999` так же.

Эндпоинты, которые нужны:

| Путь | Зачем |
|---|---|
| `GET /lol-gameflow/v1/gameflow-phase` | этап: `Lobby`, `Matchmaking`, `ReadyCheck`, `ChampSelect`, `GameStart`, `InProgress`, `EndOfGame` |
| `GET /lol-summoner/v1/current-summoner` | свой puuid и Riot ID |
| `GET /lol-champ-select/v1/session` | `myTeam[]` (cellId, puuid, championId, championPickIntent, assignedPosition, spell1Id/spell2Id), `theirTeam[]` (только championId после пика), `actions`, `bans`, `timer` |

`assignedPosition` — роль, которую назначил выбор чемпиона. Это закрывает
проблему роли `NONE` ещё до матча: советы по паку можно строить по реальной
роли, а не по самой частой.

Опрос раз в 1–2 секунды достаточен. У клиента есть и WebSocket с подпиской на
изменения (`OnJsonApiEvent_lol-champ-select_v1_session`), но cpp-httplib
WebSocket не умеет, а выигрыш в секунду здесь ничего не стоит.

### spectator-v5 — экран загрузки

`GET /lol/spectator/v5/active-games/by-summoner/{свой puuid}` на платформенном
хосте (`ru.api.riotgames.com`). Отвечает, как только игра создана, — то есть
уже на экране загрузки, раньше Live Client. В ответе `participants[]`:
`puuid`, `riotId`, `championId`, `teamId`, `spell1Id`, `spell2Id`, `perks`.

Проверено на этой машине: ключ имеет доступ (метод 3000/10 с), в Practice Tool
ответ 404 — такие игры не наблюдаемы, это ожидаемо. Форму ответа в ранговом
матче проверить при первой же обычной игре.

## Граница Riot (POLICY.md)

1. **Анонимность в выборе чемпиона не обходится.** В ранговых очередях клиент
   может скрывать имена союзников. Тогда в `myTeam[]` нет puuid, и приложение
   показывает только себя и пики — **никаких попыток восстановить, кто это**.
   Инструменты «lobby reveal» Riot запрещает прямо. Противники в выборе
   чемпиона неизвестны вовсе — и это правильно.
2. **На экране загрузки все десять имён видит сам игрок**, поэтому профили
   по spectator-v5 — это то же, что сейчас, только на минуту раньше.
3. **Из `perks` spectator-v5 ничего не показывать** сверх того, что даёт табло
   по Tab (ключевая руна и деревья). Малые руны противника игрок в матче не
   видит, и Sintence их не показывает (§9 ARCHITECTURE.md).
4. **LCU — только чтение.** Ни одного POST/PATCH: не выбирать чемпиона,
   не менять руны, не принимать матч за игрока.

## Как встроить

```
data/lcu_client        lockfile -> порт и пароль; GET с Basic-авторизацией
data/lobby_source      этап + состав: LCU в выборе чемпиона,
                       spectator-v5 на загрузке, Live Client в матче
data/profile_service   + RequestByPuuid: puuid уже известен,
                       account-v1 не нужен — 2 запроса на игрока вместо 3
app /api/lobby         этап и состав для интерфейса до начала матча
```

1. **`LcuClient`** в `data/`: найти lockfile (каталог установки →
   командная строка `LeagueClientUx.exe`), держать порт и пароль в памяти,
   `Get(path) -> optional<string>`. Разбор JSON — в `data/lcu_json.cpp`,
   наружу только типы `core/` (правило §4).
2. **`core/lobby.h`:** `LobbyPhase` (enum), `LobbyMember { puuid, riot_id,
   champion_id, position, team }`. Никаких полей, которых нет у всех трёх
   источников.
3. **`ProfileService::RequestByPuuid`**: кеш сейчас по Riot ID — добавить
   второй индекс по puuid. Профиль, заказанный в выборе чемпиона, в матче
   находится по Riot ID из Live Client без единого запроса.
4. **Фоновый поток** (как у `ProfileService`): раз в 2 с спрашивает этап.
   `ChampSelect` → свои и видимые союзники в очередь профилей;
   `GameStart` → один запрос spectator-v5 → все десять в очередь.
5. **`/api/lobby`** — `{phase, members[], assignedPosition}`; интерфейс
   показывает до матча свою карточку и союзников, на загрузке — всех.
6. **`/api/preferences`** до матча: роль из `assignedPosition`, противник по
   линии неизвестен — бакет «против всех»; после загрузки — как сейчас.

### Во что это обходится

- Запросов меньше, а не больше: puuid приходит из LCU/spectator, account-v1
  не нужен. Десять игроков — 1 (spectator) + 20 вместо 30.
- Профили союзников готовы к концу выбора чемпиона, противников — к концу
  экрана загрузки (20 запросов ≈ 25 с при лимите ключа — загрузка длится
  дольше). Карточки полные с первой секунды матча.
- Риск: LCU неофициален и может поменяться с обновлением клиента. Поэтому
  он за интерфейсом источника, и его отказ означает «как сейчас», а не поломку.

### Как проверить, когда дойдёт до реализации

1. Обычная игра (не ранговая): в выборе чемпиона `gameflow-phase` =
   `ChampSelect`, в `session.myTeam[]` у союзников есть puuid.
2. Ранговая: те же поля — есть ли puuid союзников в этом регионе. Если нет —
   показываем только себя, как решено выше.
3. Экран загрузки: spectator-v5 по своему puuid отвечает 200 и содержит
   десять участников с `riotId`.
