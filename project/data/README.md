# Данные: матчи Riot API

Курс работает с локальными файлами. Скрипт `scripts/fetch_matches.py` один раз скачивает
матчи в `project/data/matches/`, и дальше весь C++-код читает диск, а не сеть.

Так сделано намеренно. HTTP из C++ — это libcurl, зависимости и настройка сборки; если
это упадёт на тебя во время темы «классы», ты будешь месяц заниматься инфраструктурой
вместо языка. Сеть подключается в теме 15, когда для неё будет и повод, и инструменты.

## Ключ

1. Зайди на https://developer.riotgames.com, войди своим аккаунтом Riot.
2. На главной странице — блок **DEVELOPMENT API KEY**, кнопка **REGENERATE API KEY**.
3. Скопируй ключ вида `RGAPI-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.

**Ключ живёт 24 часа.** Это не ошибка и не наказание — так устроены development-ключи.
Каждый день выгрузки начинается с похода на сайт за новым.

### Как задать ключ (Windows, PowerShell)

На текущую сессию терминала:

```powershell
$env:RIOT_API_KEY = 'RGAPI-...'
```

Навсегда (в новых окнах терминала подхватится само):

```powershell
setx RIOT_API_KEY "RGAPI-..."
```

`setx` не меняет уже открытые окна — после него открой терминал заново.

Проверить, что ключ виден:

```powershell
echo $env:RIOT_API_KEY
```

Linux/macOS — `export RIOT_API_KEY=RGAPI-...` в текущей сессии либо строка в `~/.bashrc`.

**Ключ не коммитим никогда.** Ни в коде, ни в конфиге, ни в комментарии. Он живёт только
в переменной окружения. В теме 15 то же правило будет действовать для C++-клиента.

## Команда для выгрузки

Europe — это кластер, а не платформа: `euw1` и `ru` оба живут в `europe`.

```powershell
# первая настоящая выгрузка: ranked solo/duo, 500 матчей и таймлайны
python scripts/fetch_matches.py --riot-id "Имя#TAG" --region europe --queue 420 --count 500 --timeline
```

Кластеры: `europe` (EUW, EUNE, RU, TR), `americas` (NA, BR, LAN, LAS), `asia` (KR, JP),
`sea` (OCE, PH, SG, TH, TW, VN).

Очереди: `420` — ranked solo/duo, `440` — flex, `400` — normal draft, `450` — ARAM.
Без `--queue` приедет всё подряд, включая ARAM, где нет ролей и CS/min ничего не значит.

Файлы сохраняются компактно (без отступов) — так вдвое меньше места. `--pretty` возвращает
отступы, когда файл надо читать глазами.

Скрипт можно прерывать по Ctrl+C и запускать заново: уже скачанные матчи он пропускает.

## `--timeline` — включай сразу

**На первой настоящей выгрузке ставь `--timeline`.** Половина запланированного анализа без
таймлайнов не существует: смерти по минутам, удержание золота, кривая опыта, всё, что
происходит *внутри* матча, а не в его итоговой строке. История матчей у Riot конечна:
матчи хранятся около двух лет, таймлайны около года. Игры, которые выпали из истории,
добрать потом нельзя — никаким ключом.

Таймлайны качаются независимо от матчей, поэтому перезапуск на уже готовой выгрузке
добирает только отсутствующее: матчи он пропустит, таймлайны докачает.

## Сколько это места и времени

| | Один файл | 500 матчей |
|---|---|---|
| матч | 200–400 КБ | 100–200 МБ |
| таймлайн | 1–2 МБ | ещё ~0.5–1 ГБ |

С таймлайнами выгрузка на 500 игр — это около гигабайта на диске. В git ничего из этого
не попадает (`project/data/matches/`, `project/data/timelines/` в `.gitignore`).

По времени: dev-ключ даёт 100 запросов за 2 минуты, то есть ~1.2 с на запрос.
500 матчей — **примерно 11 минут**, с таймлайнами — **примерно 22 минуты**.
(Раньше здесь стояло «22 минуты на одни матчи» — это была ошибка ровно вдвое.)

## Скрипт написан для перезапусков

Это не одноразовая операция. Запусти его сейчас, потом раз в одну-две недели, и обязательно
перед темой 6 — там C++-код впервые читает каталог с данными, и ему нужен объём.
Каждый запуск требует свежего ключа (он живёт 24 часа) и догружает только новое.

## Сколько матчей качать

**200–500, не 25.** Winrate по 30 играм — это шум: один матч двигает его на три процента,
а разница между «этот чемпион у меня идёт» и «повезло» на такой выборке неразличима.
Анализатор, который печатает 70% по семи играм, врёт красивым числом.

500 матчей — это несколько запусков в разные дни (каждый день нужен свежий ключ).
Больше одного аккаунта — нормально: чем шире выборка, тем осмысленнее выводы.

Порог зашит в код с первой же задачи: `ChampionReport::kMinGamesForConclusion == 30`,
и `HasEnoughData()` честно говорит, когда выводов делать нельзя. Это одновременно фича
продукта и урок про предметную область.

## PUUID

В конце работы скрипт печатает твой PUUID и кладёт его в `matches/index.json`.
**Сохрани его.** В каждом матче десять участников, и найти среди них себя можно только
по PUUID — имя чемпиона не подходит (его мог взять кто-то ещё), номер в списке не подходит
(он не фиксирован). Это первая настоящая задача фильтрации в анализаторе.

## Что лежит в этой папке

| Путь | Что это |
|---|---|
| `sample_match.json` | один матч со всей структурой Riot, написан руками. Схема, которую можно читать, ничего не скачивая |
| `fixtures/` | три синтетических матча для тестов. Работают до того, как ты что-либо выгрузишь |
| `matches/` | реальная выгрузка. **В git не попадает** (см. `.gitignore`) |
| `matches/index.json` | список матчей, PUUID, регион, время выгрузки — создаёт скрипт |
| `timelines/` | таймлайны тех же матчей (`--timeline`). **В git не попадает** |

### Фикстуры

- `fixture_win_mid.json` — победа на миде, полные данные, длинный матч (2214 с).
- `fixture_loss_jungle.json` — поражение на лесу, короткий матч (1129 с),
  `teamPosition` у нужного участника пустой.
- `fixture_malformed.json` — **сломан намеренно**: у участника 3 нет поля `deaths`,
  у участника 7 `totalMinionsKilled` равен `null`, а `info.gameDuration` отсутствует.
  Нужен в теме 7 (ошибки) и теме 8 (парсинг). Не чини его.

Во всех трёх фикстурах «мой» участник — один и тот же PUUID:

```
753b38aaf5955163d62c2fc323d8fca3572932060f70d47a05d1b8949156f88101e215348fb08e
```

Тот же PUUID у первого участника в `sample_match.json`. В фикстурах оставлены только
те поля, которые перечислены ниже, — читать их глазами реально, а разбирать в тестах
достаточно. Полная структура со всеми полями лежит в `sample_match.json`.

## Поля, которые нужны курсу

В реальном ответе Riot несколько сотен полей на каждого из десяти участников. Анализатору
из них нужно десять. Остальные существуют, но мы их не читаем — иначе тема 8 превратится
в марафон по разбору JSON.

| Путь в JSON | Тип | Зачем |
|---|---|---|
| `metadata.matchId` | string | идентификатор матча, он же имя файла |
| `info.gameDuration` | int (секунды) | знаменатель для CS/min |
| `info.queueId` | int | отделить ranked от ARAM |
| `info.participants[].puuid` | string | найти себя среди десяти |
| `info.participants[].championName` | string | ключ агрегации |
| `info.participants[].teamPosition` | string | роль: TOP/JUNGLE/MIDDLE/BOTTOM/UTILITY |
| `info.participants[].kills` | int | K в KDA |
| `info.participants[].deaths` | int | D в KDA |
| `info.participants[].assists` | int | A в KDA |
| `info.participants[].win` | bool | winrate |
| `info.participants[].totalMinionsKilled` | int | CS: миньоны на линии |
| `info.participants[].neutralMinionsKilled` | int | CS: лесные монстры, суммируется с предыдущим |

Две тонкости, на которых легко ошибиться:

- **CS — это сумма двух полей.** `totalMinionsKilled` не включает лес. У джунглера
  без `neutralMinionsKilled` получится CS/min около нуля.
- **`teamPosition` бывает пустым.** Если игрок ушёл с линии в первые минуты, Riot не может
  определить роль. Пустая строка — валидные данные, а не повод падать. Поэтому `Champion`
  из задачи 1.1 превращает её в `"UNKNOWN"`.

## Когда ключ истёк посреди темы

Ничего не делай. Скрипт напечатает `403` и подскажет обновить ключ, но C++-код на это
не смотрит: он читает уже скачанные файлы. Иди за новым ключом, когда понадобится
следующая порция матчей, а не когда истёк предыдущий.
