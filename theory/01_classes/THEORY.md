# Тема 1. Классы, инкапсуляция, const-корректность

Справочная карточка. Глубина — в Практикуме и книгах.

## Форма класса

```cpp
class Champion {
public:
    Champion(std::string name, std::string role);          // конструктор

    [[nodiscard]] const std::string& Name() const;         // геттер: не меняет объект
    [[nodiscard]] std::string DisplayName() const;         // вычисляет, не хранит
    [[nodiscard]] bool HasRole(std::string_view role) const;

    void Rename(std::string name);                         // мутатор: меняет объект

private:
    std::string name_;                                     // поля с подчёркиванием
    std::string role_;                                     // на конце — так видно,
};                                                         // что это поле, а не
                                                           // локальная переменная
```

- `class` — по умолчанию всё `private`. `struct` — всё `public`. Разница только в этом.
- Поля **всегда** `private`. Публичное поле — это отсутствие инварианта: любой код снаружи может положить туда что угодно, и класс за это не отвечает.
- `struct` оставляем для пассивных наборов данных без инвариантов (`MatchLine` в задаче 3).

## Список инициализации

```cpp
Champion::Champion(std::string name, std::string role)
    : name_(std::move(name)),      // инициализация — до тела конструктора
      role_(std::move(role)) {     // порядок здесь должен совпадать
}                                  // с порядком объявления полей
```

Присваивание в теле (`name_ = name;`) сначала создаёт пустую строку, потом её затирает.
Список инициализации создаёт сразу нужную. Для `const`-полей и ссылок другого варианта нет вовсе.

Параметр по значению + `std::move` — стандартный приём для строк: вызывающий может
отдать временный объект без копирования. Механику `std::move` разберём в теме 2, пока
достаточно правила «строку-параметр принимаем по значению и мувим в поле».

## const-корректность

```cpp
double Kda() const;                     // метод не меняет объект
const std::string& Name() const;        // и не даёт менять то, что вернул
void Add(const MatchLine& line);        // параметр не копируется и не меняется
```

Три места, три разных `const`, и путать их — типовая ошибка первой недели:

| Где | Что значит |
|---|---|
| `const MatchLine& line` (параметр) | не копируем и не меняем аргумент |
| `... Name() const` (после сигнатуры) | метод не меняет `*this` |
| `const std::string&` (возврат) | вызывающий не может через ссылку залезть внутрь |

Правило: **метод, который не меняет объект, обязан быть `const`.** Не «желательно» —
обязан, потому что через `const Champion&` (а так его будут передавать почти всюду)
не-`const` методы просто не вызываются.

## Три вещи, которые даёт C++23 (курс собирается с ним)

**`[[nodiscard]]` на каждом методе-вопросе.** Метод, который ничего не меняет и
возвращает значение, вызывают ради результата. Если результат выбросили — это ошибка,
и пусть о ней скажет компилятор, а не тест через неделю:

```cpp
champion.HasRole("MID");     // warning C4834 / -Wunused-result: результат отброшен
```

**`std::string_view` для строковых параметров, которые только читают.** `const std::string&`
заставляет вызывающего иметь `std::string`: передал `"MID"` — создалась временная строка
с выделением памяти. `string_view` — это указатель плюс длина, он принимает и литерал,
и `std::string`, и кусок чужого буфера без копирования.

```cpp
bool HasRole(std::string_view role) const;   // "MID", name_, подстрока — всё без копий
```

Граница простая: **только читаешь строку внутри метода — `string_view`; сохраняешь её
в поле — принимай `std::string` по значению и `std::move`.** `string_view` не владеет
данными: сохранил его в поле, а исходная строка умерла — получил висячую ссылку, и ASan
покажет `heap-use-after-free`.

**`std::format` вместо склейки строк.** `DisplayName()` — это одна строка, а не три
конкатенации:

```cpp
return std::format("{} ({})", name_, role_);          // "Ahri (MIDDLE)"
return std::format("{:.2f}", kda);                    // "2.50" — округление в формате
```

Строка формата проверяется на этапе компиляции: лишняя `{}` или `{:.2f}` для `int` —
ошибка сборки, а не мусор в отчёте. Печать в консоль — `std::println` из `<print>`
(тема 4), сборка строки — `std::format` из `<format>`.

Сигнатуры уже сгенерированных задач 1.1–1.3 переписывать не нужно: `const std::string&`
там корректен. Начиная с новых задач — по правилу выше.

## Пять ошибок этой темы

| Что сделал | Что увидишь |
|---|---|
| вызвал не-`const` метод у `const`-объекта | `C2662: невозможно преобразовать "this" из "const Champion" в "Champion&"` / `passing 'const Champion' as 'this' argument discards qualifiers` |
| объявил метод `const` в `.h`, забыл `const` в `.cpp` | `LNK2019` — для линкера это две разные функции (привет, тема 0) |
| обратился к полю снаружи класса | `C2248: невозможно обратиться к private член` / `'name_' is private within this context` |
| вернул ссылку на локальную переменную | компилируется, потом ASan печатает `stack-use-after-scope` |
| поля в списке инициализации в другом порядке, чем объявлены | `C5038` / `-Wreorder`: инициализируются они всё равно в порядке объявления |

## Целочисленное деление

```cpp
int kills = 10, deaths = 4;
double kda = kills / deaths;                             // 2.0 — потеряли остаток
double kda = static_cast<double>(kills) / deaths;        // 2.5 — верно
```

`int / int` — это `int`, и приведение результата к `double` уже ничего не спасает.
Приводить надо **до** деления. В KDA, winrate и CS/min ты наступишь на это трижды.

## Читать в книгах

- **«Чистый код», глава 2 «Содержательные имена».** `Kda()` вместо `Calc()`, `games_played_` вместо `n`. Правило «имя должно отвечать, зачем оно существует» — вся эта тема про то, чтобы `champion.Winrate()` читалось без комментария.
- **«Чистый код», глава 6 «Объекты и структуры данных».** Ключевое различие: объект прячет данные и показывает поведение, структура данных показывает данные и не имеет поведения. `PlayerStats` — объект, `MatchLine` — структура данных. Здесь же «закон Деметры» — почему `report.Player().Stats().Kills()` плохо.
- **«Чистый код», глава 10 «Классы».** Класс должен быть маленьким, и мерять его надо количеством обязанностей, а не строк. Примеры на Java: там `private` + геттеры — обязательный ритуал, в C++ можно вернуть `const&` и не копировать. Смысл тот же, цена другая.
